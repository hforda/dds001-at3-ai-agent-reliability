## 三、可在缺失輸入下先行完成的部分（不依賴來源包）

以下工作**完全不依賴來源包實體**，可在計劃確認後立即執行，且不會產生任何「假數據」風險：

### 3.1 工程骨架與執行器（純 Python 標準庫）

```
AT3_03_Agent_Work_Task/
├── README.md                    # 執行與複核說明
├── requirements.txt              # 註明：核心路徑僅需標準庫
├── environment.txt               # 環境快照
├── src/
│   ├── agent_loop.py             # Agent 主迴圈（搜索→讀取→綜合→停止）
│   ├── tools.py                  # 三個工具：search_sources / read_source / write_brief
│   ├── tool_schema.json          # 工具 schema（含清楚的參數、回傳值、副作用）
│   ├── task_contract.json        # 目標、約束、完成條件
│   ├── validate_final_state.py   # final-state validator（gate 由 §五 定義）
│   ├── run_lab.py                # --check / --run / --compare 入口
│   └── compare.py                # max_steps 受控比較（單變數）
├── source_pack/                  # ← 來源包插槽：空 + README 說明所需格式
├── results/                      # trajectory.jsonl / tool-results.jsonl / evaluation.csv / comparison.csv
├── final-brief.md                # 執行後產出
├── error-note.md                 # 失敗分析
├── provenance.json               # 真實 provenance
└── analysis.md                   # 兩頁以內分析
```

### 3.2 先行交付的「契約層」（可獨立複核）

- `task-contract.json`：目標、約束（離線、免 API/模型/GPU/網路）、完成條件、**validator gate 清單**。
- `tool-schema.json`：工具名稱、參數型別與語義、回傳結構、副作用（唯讀 vs 寫入）、錯誤語義。
- `validate_final_state.py`：**檢查最終交付狀態**（而非僅檢查檔案存在）：簡報是否含三個唯一 citation、每個 citation 是否對應一次實際 `read_source` 觀測、citation 內容是否可在該觀測文本中回查、步數是否在預算內。
- `run_lab.py --check`：零依賴自檢。

### 3.3 Agent 迴圈的設計（不依賴來源包內容）

Agent 為**規則式（deterministic）工具調用迴圈**，非 LLM 代理：

```
step 1  search_sources(query)      → 取得候選來源清單（僅索引，不讀全文）
step 2..k  read_source(source_id)  → 取得該來源全文與可定位段落（citation 錨點）
step k+1  write_brief()            → 以已讀來源撰寫一頁簡報，逐一標註 citation
停止條件：已讀三個來源且簡報完成（提前停止）／步數用盡（安全停止）
```

此設計使 `max_steps=3` vs `max_steps=6` 成為**真實可觀測的資源預算效應**：3 步不足以完成「1 次搜索 + 3 次讀取 + 1 次撰寫」，6 步則可能。這正是課程希望比較的變數，且不需外部模型。

### 3.4 失誤分析素材

`error-note.md` 需涵蓋：失敗定位、錯誤層級（goal / tool choice / argument / observation / state update / stop）、錯誤訊息、是否可 retry、為何「重試」不等於「重新規劃」、正確的 recovery 方式。這可在迴圈實作後，用**真實執行中被截斷的軌跡**填寫，而非虛構。

## 四、來源包到位後的執行流程（無需再改設計）

1. 將來源包放入 `source_pack/`，其格式需求寫在該目錄 README（供使用者或教師對照）。
2. `python src/run_lab.py --check` → 確認來源包索引可建。
3. `python src/run_lab.py --run --max-steps 6` → 產出真實 trajectory / tool-results / final-brief。
4. `python src/run_lab.py --run --max-steps 3` → 獨立輸出目錄，不覆蓋。
5. `python src/run_lab.py --compare` → 產出 comparison.csv（僅改 max_steps 一個變數）。
6. `python src/validate_final_state.py` → 對兩組結果各跑 validator，逐 gate 記錄。
7. 填 `error-note.md`、`analysis.md`、`provenance.json`。

## 五、final-state validator gate 定義（**本計劃提案，待確認**）

因課程未給 gate 清單，以下依課程四項交付物推導，**作為提案而非既定要求**：

| Gate | 判定條件 | 對應課程要求 |
|---|---|---|
| `brief_exists` | `final-brief.md` 存在、非空、含 ≥1 個 citation 標記 | 「生成一頁含 citation 的研究簡報」 |
| `three_unique_citations` | 簡報中出現 **3 個互異** citation 標記 | 「讀取三個相關來源」 |
| `citations_were_read` | 每個 citation 對應的來源，在 trajectory 中存在**一次成功的 `read_source` 觀測** | 「不得把搜索結果摘要冒充完整閱讀證據」 |
| `citation_traceable` | 每個 citation 的引文片段可在該 `read_source` 觀測文本中**逐字回查** | 「引用必須能回溯到實際來源」 |
| `three_sources_read` | trajectory 中成功 `read_source` 的**互異來源數 ≥ 3** | 「讀取三個相關來源」 |
| `within_step_budget` | 實際執行步數 ≤ 該次設定的 `max_steps` | 受控比較的變數 |

> **注意**：`citations_were_read` 與 `citation_traceable` 是**兩層不同**的證據強度，後者直接對應課程「不得把搜索結果摘要冒充完整閱讀證據」「不得編造 citation」。

| 保持不變 | 只有這一項改變 |

| 工具 schema 與參數語義 | |

比較指標（寫入 `evaluation.csv` 與 `comparison.csv`）：

| 指標 | 定義 |
|---|---|
| `task_completed` | 六項 gate 是否全通過（布林） |
| `gates_passed` | 通過 gate 數 / 6 |
| `effective_tool_calls` | 產生有效觀測的工具調用數（區分於總調用數） |
| `total_tool_calls` | 總工具調用數 |
| `sources_read` | 成功讀取的互異來源數 |
| `citations_valid` | 可逐字回查的 citation 數 |
| `failure_mode` | 首個失敗步驟及其錯誤層級 |

**預期方向（待實測驗證，不預先寫死）**：步數預算增加應提高 `task_completed` 與 `sources_read`；若出現「步數變多但 citation 品質不變」或「步數用盡型失敗占比上升」等非平凡結果，將如實記錄並在 `analysis.md` 討論。
