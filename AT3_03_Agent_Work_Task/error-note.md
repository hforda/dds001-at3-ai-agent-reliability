## 二、第二輪的錯誤層級與恢復策略

### 2.1 錯誤層級定義

沿用 Agent 系統的標準分層：

| 層級 | 意義 | 本輪實例 |
|---|---|---|
| **goal** | 任務目標理解錯誤 | Agent 誤以為要「多讀幾篇」而非「讀三篇＋寫簡報」 |
| **tool choice** | 選錯工具 | 連續呼叫 `search_sources`（選擇迴圈）；已讀三篇後仍呼叫 `read_source` |
| **argument** | 工具參數錯誤 | 幻覺出不存在的 doc_id；用單引號而非雙引號；輸出被截斷導致閉引號遺失 |
| **observation** | 對回傳結果的處理錯誤 | 把論文標題當成 bullet 文字；把句子改寫成自己的概括 |
| **state update** | 內部狀態更新錯誤 | 引用了未讀過的文件；同一 marker 對應多條 bullet |
| **stop** | 停止條件錯誤 | 在未寫出簡報時用盡步數預算 |

### 2.2 各失敗形態、證據與恢復

#### E1 — 幻覺 doc_id（tool choice / argument）

- **證據**：`read_source(doc_id="2301.11659v2")` 被工具層拒絕。
  該 id 格式雖合法，但**不在任何一次 `search_sources` 的候選清單內**——
  它是模型從記憶中虛構的（該 id 的真實論文主題為
  "Matching Linear Algebra and Tensor Code to Specialized Hardware Accelerators"，
  與任務主題 LLM Evaluation 無關）。
- **錯誤層級**：argument（參數取值來自記憶而非檢索結果）
- **恢復策略**：工具層 **allowlist**。`read_source` 僅接受「曾由 `search_sources`
  回傳過」的 doc_id，否則立即拒絕並回灌可用候選清單。
- **安全停止**：不允許讀取，即模型無法藉此產出無來源依據的引用。

#### E2 — 重複讀取同一文件（goal / tool choice）

- **證據**：`step 4` 曾以 `read_source(doc_id="2301.12004v1")` 重讀已讀文件，
  浪費一個步數預算。
- **錯誤層級**：goal（Agent 未追蹤「已讀哪些」）
- **恢復策略**：工具層 **重複讀取保護**——已讀過的 doc_id 再次請求時直接拒絕，
  並回灌「已讀清單 / 未讀清單」與「若已讀滿三篇請立即 write_brief」的指示。

#### E3 — 讀滿三篇後仍繼續讀取（goal / stop）

- **證據**：曾出現讀滿三篇後仍呼叫 `read_source` 的情況，把步數預算耗在無效動作上。
- **錯誤層級**：goal + stop
- **恢復策略**：工具層 **讀滿即停**——`required_sources=3` 達成後，`read_source`
  一律拒絕並要求立即 `write_brief`。此約束不決定「讀哪三篇」，
  選擇權仍完全屬於模型。

#### E4 — 連續重複檢索（tool choice）

- **證據**：模型曾連續四步呼叫 `search_sources`，每次同一 query，
  每一步都在「從同一批候選中挑選」而未推進到讀取階段。
- **錯誤層級**：tool choice
- **恢復策略**：
  (a) `top_k` 限制在 3–6，避免候選過多導致選擇困難；
  (b) 每步狀態中明示「已檢索 N 次，不要再檢索」與
      「YOUR NEXT ACTION MUST BE read_source on one of the not-yet-read doc_ids」。

#### E5 — 把論文標題當成 bullet 文字（observation）

- **證據**：曾輸出
  `- **The effectiveness of very large language models on dialog evaluation** [doc_id:2301.12004v1#s7]`
  —— 該文字是**標題**，不是來源句，逐字核驗必然失敗。
- **錯誤層級**：observation（模型未區分「元資料」與「可引用句」）
- **恢復策略**：
  (a) 呈現給模型的句子清單中**不呈現標題**；
  (b) Prompt 明示「標題只供參考，不得作為 bullet」，
      並給出可判別的啟發式：像標題（無動詞、無句末句號）= 錯；
      像論文句子（有動詞、有句號）= 對。

#### E6 — 自行概括來源句（observation）

- **證據**：曾輸出
  `- **Technical Roadlines**: Bayesian lens, in-context learning, and latent variable models are used to evaluate LLMs. [doc_id:2301.11916v3#s7]`
  —— 這是模型自己的概括，**在任何來源句中都不存在**。
- **錯誤層級**：observation
- **恢復策略**：Prompt 明示「bullet 永遠是某一條 s[] 行的逐字複製」，
  並以「copied sentence」與「your own summary」對照。

#### E7 — 句號與 doc_id 歸屬錯配（observation / state update）

- **證據**：曾輸出
  `- The evaluation of the quality of the generated text is a complex problem. [doc_id:2301.12004v1#s4]`
  —— 該句實際出自 `2303.15078v3` 的 `s[4]`。
- **錯誤層級**：observation（句子取自一篇、marker 卻掛到另一篇）
- **恢復策略**：
  (a) 呈現句子時把 doc_id 置於**行首**，格式與 citation marker 前綴一致；
  (b) 核驗失敗時給出**精確診斷**：指出該句原文實際出自哪一篇的哪一句，
      要求 Agent 自行修正 marker。
  **工具端絕不自動改寫 marker**——修正必須由模型在下一步完成。

#### E8 — 輸出被截斷 / 退化（argument）

- **證據**：3B 模型在解碼接近上限時會退化為無限重複的 ``` 圍欄，
  導致 `brief_text` 的閉引號遺失、參數解析失敗（`missing_brief_text`）。
- **錯誤層級**：argument
- **恢復策略**：解析層以括號配對掃描取代貪婪正則；支援單雙引號；
  提供截斷補救分支；停止序列加入 ``` 以提前截斷退化。

#### E9 — 在長對話中模仿對話歷史（argument / state update）

- **證據**：手工拼接的純文字 prompt 下，模型會續寫
  `Action: read_source(...) Observation: READ ...` 而非產出新規劃，
  甚至憑空生成 `2303.15622v2` 這類不存在的 doc_id。
- **錯誤層級**：argument（輸入結構不匹配模型訓練分布）
- **恢復策略**：改用模型自帶的 **chat template**（system + user 兩段式），
  每步重述當前狀態而非餵回完整對話歷史。

## 三、第二輪最終的實際執行結果

### 3.1 max_steps = 3（`results/run_maxsteps3/`）

| step | 工具 | ok | 說明 |
|---:|---|---|---|
| 1 | `search_sources` | ✅ | query=`large language model evaluation`, top_k=5 |
| 2 | `read_source` | ✅ | `2301.12004v1` |
| 3 | `read_source` | ✅ | `2303.15078v3` |

**停止原因**：`max_steps_reached`。
**結果**：只讀到 2 篇，未寫出簡報 → validator **FAIL 3/8**。
**失敗性質**：**預算耗盡型**（行為序列本身正確，只是走不到寫作步），
不是行為錯誤型。

### 3.2 max_steps = 6（`results/run_maxsteps6/`）

| step | 工具 | ok | 說明 |
|---:|---|---|---|
| 1 | `search_sources` | ✅ | query=`large language model evaluation`, top_k=5 |
| 2 | `read_source` | ✅ | `2301.12004v1` |
| 3 | `read_source` | ✅ | `2303.15078v3` |
| 4 | `read_source` | ✅ | `2301.11916v3` |
| 5 | `write_brief` | ✅ | 簡報寫入成功，三條引用全部逐字通過 |

**停止原因**：`brief_written`（**第 5 步即完成，實際只用 5 步**）。
**結果**：讀滿 3 篇、簡報成功、3 個互異引用全部可逐字回查 →
validator **PASS 8/8**。

> 注意：6 步組在第 5 步就完成，**第 6 步未使用**。這說明在嚴格引用規則下，
> 「檢索 1 步 + 讀取 3 步 + 寫作 1 步 = 5 步」已足以完成任務；
> 若首次寫作被逐字核驗拒絕而需重試，則需要第 6 步。

## 四、嚴格引用規則的實現與「工具不作弊」的保證

第二輪的核心修正是引用規則。為避免「把生成簡報等同於完成 Agent 任務」，
實作上明確劃出界線：

### 4.1 工具端**不做**的事（第一輪的缺陷）

| 第一輪的行為 | 第二輪 | 對應任務單條目 |
|---|---|---|
| 以**詞彙重疊**自動在來源包中「找最佳來源句」 | **已移除**（`_autofill_sentence_ids` 整個方法刪除） | C3-5 |
| 自動**替換**模型寫錯的 `#sN` | **已移除**（無任何自動改寫 marker 的程式路徑） | C3-5 / C4-6 |
| 模型只寫 2 篇時**自動補足第三篇**的 marker | **已移除** | C3-5 |
| 引用有效性以「一個共同內容詞」判定 | 改為**逐字包含**判定（僅容許空白字符歸一化） | C4-4 / C4-5 |
| 語義支持為硬門禁後又降級為診斷 | 門禁恢復為**逐字核驗**；詞彙重疊率改名 `lexical_overlap_rate` 且**僅作診斷** | C4-7 |

### 4.2 工具端**仍會做**的事（合法的輔助）

1. **allowlist 與重複讀取保護**：約束「可以讀什麼」，屬於安全邊界。
2. **逐字核驗與精確診斷**：核驗失敗時告知模型
   「你貼的這句其實出自 X 的 s[N]」——這是**回饋資訊**，
   模型必須在下一步**自己**修正 marker；工具端不改寫。
   比對規則是**精確包含**（來源句原文逐字出現在 bullet 內），不是詞彙重疊。
3. **Prompt 溢出清理**：移除模型尾端續寫的 Prompt 指令行（純格式清理，
   不改動任何 bullet 或引用文字）。
4. **可照抄 bullet 模板**：把模型**已讀**文件的可引用句子整理成可直接複製的
   三條 bullet 形式。這**不決定引用哪三篇**——那仍是模型自主選出的已讀文件；
   工具只提供「照抄材料」，模型仍須決定寫入哪三條、標題與摘要怎麼寫。

### 4.3 「可照抄模板」是否算「預設固定順序」？

不算。區別如下：

- **Agent 循環仍是真實的**：模型每一步根據當前任務與 observation 決定下一動作；
  實際軌跡顯示模型自主發出了 `search_sources`、連續三次 `read_source`
  （每次自行選出不同的 doc_id）、以及 `write_brief`。
- **選哪些來源由模型決定**：模型選了 `2301.12004v1`、`2303.15078v3`、
  `2301.11916v3` 三篇；工具從未指定這三篇。
  （第一輪曾出現 `2301.11659v2` 這個與主題無關的來源，本輪已被 allowlist 與
  候選排序排除。）
- **模板只針對已讀文件**：若模型只讀了兩篇，模板只會有兩條，
  `write_brief` 仍會因互異來源不足三個而被拒。

## 五、安全停止條件

| 條件 | 行為 |
|---|---|
| 步數預算耗盡 | 立即停止，寫出當前 trajectory 與 tool-results，不強行補寫簡報 |
| 引用逐字核驗失敗 | 拒絕寫入，回灌可操作的診斷，等待模型下一步修正 |
| 引用互異來源不足三個 | 拒絕寫入，列出已讀文件清單 |
| 格式錯誤（無法解析動作） | 計入 `format_errors`，回灌格式要求；超過上限則停止 |
| 重複讀取 / 讀滿三篇後再讀 | 工具層拒絕 |
| 讀取非候選 doc_id | 工具層拒絕 |

**不存在**任何形式的「工具代填引用」「自動補齊來源」「自動改寫 marker」。

## 六、仍然存在的限制

1. **單次運行，無跨次方差估計**。兩組各只跑一次，
   結果不能推廣為「6 步必然成功」。溫度為 0 的貪心解碼使 run-to-run 方差很小，
   但未實測。
2. **3B 模型的引用能力是本實驗的主要瓶頸**。實測中模型能逐字複製，
   但在候選句較多、上下文較長時會同時犯「改寫」「錯配 doc_id」
   「三條取自同一篇」三類錯誤。本輪能達成 8/8 PASS，
   關鍵在於工具層把候選收斂到單句並提供可照抄格式。
   這是**工程輔助**，不是模型能力的自然湧現——**不可推廣為 3B 模型的一般能力陳述**。
3. **來源包規模有限**：1,491 篇、`cs.CL` 僅 49 篇。
   主題簇密度限制了「讀三篇真正相關的評價論文」的可得性。
4. **語義蕴含未被驗證**。本輪的門禁是**逐字**判定，
   證明的是「引文確實是來源原句且確在該 bullet 中」，
   **不證明**「該句在語義上充分支持該 bullet 的論斷」——
   後者需要人工審查或語義蕴含模型，超出本作業範圍。
   詞彙重疊率僅為診斷指標，**不具語義驗證效力**。
5. **GPU 熱降頻**：RTX 3070 Laptop 連續負載時時鐘由 2100MHz 降至約 1100–1500MHz，
   單次推理耗時因此從約 4s 波動到 240s 以上。這影響**耗時**，
   不影響結果內容（貪心解碼）。
6. **頁眉雜訊句的處理**：arXiv 轉檔的前幾句常含作者郵箱、日期戳等雜訊。
   本輪在**呈現層**過濾這些句子，但**保留其全局句號**，
   故 citation 座標仍與來源包完全一致；這些句子仍存在於 `documents.jsonl` 中，
   只是不作為引用候選。
