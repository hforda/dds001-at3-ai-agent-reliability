## 一、研究範圍與問題

本輪僅執行《累積式大作業（AT3）設計.md》之 ① 文獻綜述，未執行技術復現、Agent 工作任務、AT4 Final Report，未進行任何 GPU 訓練或大型推理實驗。**本輪為純文獻研究**：文中提及的 Border Event Intelligence Agent 尚未實作、無任何實測結果，亦不主張 Agent 能解決負遷移預測問題。

研究以 AI Agents 為主體，嚴格區分 LLM／LLM-based Agent／Tool-using Agent／Multi-Agent System／Agent Workflow 五個概念——判別標準是是否存在跨步驟行動、工具互動與基於回饋的修正；單次 Prompt 與一般 RAG 不計入 Agent。依任務書指定方向組織為五類：**A 基礎架構與推理規劃、B Tool Use 與工作流編排、C Memory 與 Multi-Agent、D 評估與可靠性、E 實際應用**。

## 三、核心判斷

**領域瓶頸不是論文不足，而是度量語言互不相通**——ReAct 量單次任務完成率、AgentBench 量 8 環境加權總分、τ-bench 量「對話＋政策約束下的終態正確性與跨試驗一致性」、WebThinker 量知識密集推理與報告品質；排進同一排行榜是方法論錯誤。基於此提出八項批判性主張，三項最具代表性：

- **Q2 平均值掩蓋尾部崩潰**：單次成功率 61.2% 與 pass^8 < 25% 之間落差意味線上多數使用者都會撞上一次失敗。
- **Q5 防禦與效用此消彼長**：提示注入檢測器把攻擊成功率壓至 7.95%，卻讓無攻擊效用由 69.00% 崩至 41.49%；唯一正解是工具隔離（ASR 6.84% / 效用 73.13%）。
- **Q8 證據可追溯性從未被主流 Agent 基準評分**：GAIA 明文不評推理軌跡，AgentBench 分解的是「為何失敗」而非「由哪些證據支撐」，WebThinker 的 Factuality 評的是敘述而非證據鏈——此為最大空白。

其餘：Q1 度量語言割裂；Q3 顯式思考步驟不保證可靠性（τ-bench `think` 函數消融無增益）；Q4 多智能體收益來自異質性與角色專用化而非數量；Q6 檢索召回仍是瓶頸（ReAct 23%、ToolLLM 22%）；Q7 基準衰減快於方法迭代。

## 四、對博士研究的意義

面向多源資訊獲取、事件抽取、證據核驗與結構化資料構建，提出七項可操作設計：① 證據可追溯性設為一級目標（每筆記錄攜帶 source spans 與信心度，可被確定性檢查器驗證）；② 評估拆為「來源召回率 × 欄位填寫正確率」雙維度；③ 同報 pass^1 與 pass^k，重試變因為「同一事件、不同來源表述」；④ 角色即職責邊界（蒐集者只讀／抽取者／衝突檢測者／格式化者，上下文嚴格隔離）；⑤ 以 schema 校驗與欄位斷言替代 LLM 判斷，證據不足顯式棄權；⑥ 檢索內容一律視為資料而非指令並報效用＋注入成功率；⑦ 自建基準須內建失效偵測與輪換。**以上皆為設計推導，非實證結論。**

## 五、研究空白與後續工作（依優先次序）

1. **證據可追溯性的評分方法學**（信心度：高）——可建立 provenance 失效分類（引用不存在／引用與結論矛盾／引用不足以支撐結論），此設計無法從任何現有論文直接借用，須自行建立。
2. **可靠性指標的異質任務聚合**（高）——k 的選取與「同表述 vs 同義不同表述」兩種變因的比較尚無標準。
3. **探索性不足場景的反思機制**（中）——Reflexion 的 WebShop 失敗實驗留下空白，多源廣度檢索正處此困境。
4. **基準壽命週期管理**（中高）——面向資源受限實驗室的輕量失效偵測方法。
