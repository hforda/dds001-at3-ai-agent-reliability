## 摘要

AI Agent 已從「單次提示詞工程」演進為一類具有獨立架構、方法論與評估體系的學科對象。本綜述以 8 篇核心論文為主軸（含 5 篇 2024 年及以後頂會正式錄用論文），依任務書指定的五個方向——**A 基礎架構與推理規劃、B Tool Use 與工作流編排、C Memory 與 Multi-Agent、D 評估與可靠性、E 實際應用**——建立統一文獻矩陣與結構化知識圖譜。

綜述的核心判斷是：這個領域的真正瓶頸**不是論文數量不足，而是度量語言互不相通**。ReAct 量的是單次任務完成率、AgentBench 量的是 8 環境加權總分、τ-bench 量的是「在模擬使用者對話與領域政策約束下的終態正確性與跨試驗一致性」、WebThinker 量的是「知識密集推理與長報告品質」——把這些分數排進同一張排行榜是方法論錯誤。在此基礎上提出八項批判性主張，其中最具原創性的三項是：（Q2）單次成功率系統性掩蓋尾部崩潰，gpt-4o 在 τ-retail 的 pass^1 為 61.2 但 pass^8 掉到 25% 以下；（Q5）安全防禦與任務效用存在可量化的此消彼長——純提示注入檢測器把攻擊成功率壓到 7.95%，卻讓無攻擊效用從 69.00% 崩到 41.49%；（Q8）**證據可追溯性至今未被任何主流 Agent 基準正式評分**，這是本綜述判定的最大研究空白。

針對博士研究的應用場景（多源資訊獲取、事件資訊抽取、證據核驗、結構化資料構建），本綜述給出可操作的遷移設計：把證據可追溯性設為一級目標、以「來源召回率 × 欄位填寫正確率」雙維度評估、以 pass^k 而非單次成功率衡量可靠性、並以「角色即職責邊界」的嚴格隔離架構取代通用多智能體堆疊。

## 二、研究背景與應用定位

本綜述兼顧計算機科學方法與實際應用，重點落在**多源資訊獲取、事件資訊抽取、證據核驗與結構化資料構建**這一類任務上。選擇這個場景的理由不是它「熱門」，而是因為它是 agent 能力結構的**壓力測試**：它同時要求（i）多來源檢索與召回，（ii）跨來源的事實抽取，（iii）對抽取結果的正確性判斷，（iv）可追溯的結構化產出。這四項恰好對應四個分類方向，而現有文獻在這四項上的成熟度極不均衡——檢索與抽取工具相對成熟（D 類評估卻嚴重落後），而證據核驗幾乎是空白（Q8）。

與博士研究的潛在聯繫在於：目前研究方向涉及多口岸客流時間序列預測、多源資料融合、異常事件分析與負遷移風險識別；未來可探索構建 **Border Event Intelligence Agent**，執行四步流程——

1. 檢索政府公告、新聞及其他公開來源；
2. 提取事件時間、地點、類別與影響範圍；
3. 跨來源交叉核驗證據；
4. 生成可追溯的結構化事件記錄；

再為後續客流預測與異常分析提供**外部資訊**。

必須強調三點邊界：（i）本輪僅為文獻研究，上述系統**尚未實作**，本文不含任何實測結果；（ii）Agent 提供的是可追溯的外部資訊，其對預測模型的增益屬於**未經驗證的假說**；（iii）不得據此主張 Agent 能夠解決負遷移預測問題——負遷移是統計學習層的現象（跨節點特徵分布差異導致的轉移損害），與 Agent 的資訊獲取能力屬不同因果層級。

## 四、分類綜述

### A. Agent 基礎架構與推理規劃

**架構原型：ReAct（P1）**。ReAct 的核心貢獻是把長期被分開研究的「推理」與「行動」合併為一個交錯循環：動作空間從 A 擴充為 Â = A ∪ L，其中 L 是語言（thought）空間；上下文按 c(t+1) = (c(t), â(t)) 累積，其中 thought 不改變環境、只更新上下文，action 則改變環境並產生 observation。在知識密集任務上採稠密交錯，在互動決策任務上採稀疏交錯——由模型自主決定何時插入 thought。

這裡有一個容易被二手轉述掩蓋的細節：**純 ReAct 在 HotpotQA 上的 EM 為 27.4，低於 CoT-only 的 29.4**。常被引用的 35.1 實為 ReAct→CoT-SC 的混合策略；而在 FEVER 上 ReAct（60.9）確實優於 CoT（56.3）。這個細節改變了對 ReAct 的理解：它的價值不在於「每個指標都更強」，而在於**接地（grounding）帶來的幻覺抑制**——失敗案例中 CoT 的幻覺率為 56%，ReAct 為 0%；成功案例的假陽性率由 14% 降至 6%。代價是推理錯誤率從 16% 升至 47%（交錯結構降低了推理的靈活性）。

**錯誤恢復：Reflexion（P2）**。Reflexion 處理的是另一個問題：agent 如何從試錯中學習。它以 Actor / Evaluator / Self-Reflection 三模組構成試錯循環，用「口頭強化學習」——以自然語言的語意梯度取代數值梯度——在不更新權重的前提下獲得學習訊號。長期記憶是一個容量固定的滑動視窗（ALFWorld 3 條、HotPotQA 3 條、程式任務 1 條）。

Reflexion 的數據同樣需要精確解讀：HumanEval(Python) pass@1 達 91.0%，高於 GPT-4 的 80.1%，這是文獻中最常被引用的結果；但 **MBPP(Python) 只有 77.1%，低於其自身 baseline 的 80.0%**。論文給出的解釋是自生成測試的假陽性率——MBPP 上達 16.3%，而 HumanEval 僅 1.4%。這條證據的價值在於它界定了一個上限條件：**當「自動測試」本身不可靠時，整個反思迴路會被污染**。而最關鍵的消融是：只有測試生成而無反思時性能不變（0.60→0.60），只有反思而無測試生成時反而下降（0.60→0.52），兩者兼具才達 0.68。這證明**單純的試錯不足以帶來改進，必須有把「發現錯誤」連接到「改變實現」的歸因機制**。

Reflexion 的 WebShop 失敗實驗同樣重要，作者誠實報告：two-shot ReAct + Reflexion 在 100 個環境上執行 4 輪後即無改進，且失敗後**無法產生有幫助的反思**。這意味著反思機制對「需要大量多樣性探索」的任務無效——ALFWorld 能成功是因為環境會顯示允許的動作，探索成本低；而電商搜尋的歧義處理超出了其能力。

**跨文獻判讀（Q3）**：把 ReAct 與 Reflexion 並置可得一個重要結論——**顯式推理步驟的增加並不保證可靠性**。P2 的消融顯示反思的價值在「歸因」而非「反思」本身；後續 τ-bench（P7）的消融更直接：給 function-calling agent 增加一個顯式 `think` 工具**並未帶來提升**。真正有效的機制是能改變**動作選擇**的機制——回溯（ToolLLM 的 DFSDT）、選擇性放棄（`Finish by Giving Up`）、可執行判據（ChatDev 的編譯／執行回饋）。

### B. Tool Use 與工作流編排

**ToolLLM（P4）是本方向的核心文獻**，它罕見地同時提供資料、訓練與評測三層。ToolBench 的規模為 16,464 個 API／3,451 個工具／49 個大類，最終得到 197,479 個合格指令-API 對與 126,486 個指令-解路徑對，涉及 469,585 次真實 API 呼叫。

其最具工程價值的機制是 **DFSDT（深度優先搜尋決策樹）**。它相對於 ReAct 的改進有兩層：一是允許模型**撤回**當前路徑並擴展一個不同的節點（對應「走錯了不從頭來」）；二是放棄對子節點的排序——論文發現「排序最高的往往就是第一個生成的」，而排序需要 LLM 兩兩比較（約 O(n log n) 次 API 呼叫），故直接採 pre-order traversal。效果是 DFSDT 平均 Pass Rate 63.8% vs ReACT 35.3%（+28.5pp）；**在同預算對齊後（vs ReACT@N 44.5%）仍領先 19.3pp**，這排除了「多花 token 就會贏」的替代解釋。增益隨任務複雜度遞增：多工具場景 I3 達 +35.2pp。

兩個容易被忽略但極有價值的細節：

- **神經 API 檢索器（NDCG@1 78.0）優於 oracle API 集**。加 top-5 檢索注入的版本（67.3）反而略高於使用標準答案 API 集（66.7）。這說明「檢索增強」不僅不劣於硬編碼來源清單，還可能找到功能更優的替代來源——對多源資訊系統是重要的實證支持。
- **Vicuna 與 Alpaca 在大量提示工程後 Pass 與 Win 全為 0**。這是「通用能力不自然遷移到工具域」的明確警示。

**跨文獻判讀（Q6）**：檢索召回是這個方向的結構性瓶頸，但多數框架把它當成已解決問題。ReAct 的錯誤分析顯示 **23% 的失敗源於非資訊性檢索**（搜到了但無用，且會使推理脫軌難以恢復）；ToolLLM 的檢索器 NDCG@1 為 78.0，意謂約 22% 的正確工具在第一時間根本不會被選中。這個比例與 WebThinker 的消融方向一致：移除 Deep Web Explorer 使綜合均分從 42.1 跌至 38.3，而僅禁用連結點擊只從 42.1 跌至 42.6——**深挖（導航）比淺搜（搜尋）關鍵得多**。

### C. Memory 與 Multi-Agent Collaboration

**記憶架構：Generative Agents（P3）**。這篇 UIST Best Paper 貢獻了目前仍最常被引用的記憶四件套：記憶流（自然語言完整記錄）、三軸加權檢索、反思、以及規劃與反應。檢索評分為 α_recency·recency + α_importance·importance + α_relevance·relevance，三個分數皆以 min-max 正規化、α 全設為 1：recency 為指數衰減（係數 0.995），importance 由 LLM 給 1–10 整數，relevance 為 query 與記憶的 embedding 餘弦相似度。反思在近期事件重要性總和超過 150 時觸發（實務上每日約 2–3 次），生成 5 條高層洞察，**並保留「because of 1, 2, 8, 15」形式的引用指標**。

消融數據支持架構的必要性：完整架構 TrueSkill μ=29.89，去反思 26.88，去反思去計畫 25.64，全消融 21.21，完整 vs 全消融 Cohen's d = 8.16，Kruskal–Wallis H(4) = 150.29、p < 0.001。端到端結果更直觀：派對消息的知情者從 1 人（4%）增至 13 人（52%），關係網路密度從 0.167 增至 0.74。

但這篇論文最值得博士研究借鑑的，不是消融數字，而是那個**「摘要 + 引用指標」的雙層結構**。它意味著高層洞察並非無根據的臆測，而是保留了通往底層觀測的指針。這正是證據可追溯性的原始雛形——只是它服務於 agent 自身的長期記憶，尚未被提升為通用評分維度（見 Q8）。

同時必須注意其幻覺形態：453 個關於其他智能體的回答中有 1.3%（n=6）為幻覺，且**多為擴寫而非捏造**——真實事件加上無依據的細節（把鄰居 Adam Smith 說成《國富論》作者）。這種「部分正確 + 細節虛構」比完全捏造更難偵測，對事件抽取系統是更隱蔽的風險。

**多智能體編排：ChatDev（P5）**。ChatDev 貢獻了 Chat Chain（說什麼）與 Communicative Dehallucination（怎麼說）雙機制。後者的核心是**角色反轉（role reversal）**：Assistant 主動以 instructor 口吻反問缺失資訊（例如外部依賴的準確名稱及其類別），再給出結論性回答。其記憶設計同樣值得注意——短期記憶維持階段內對話連續性，長期記憶**跨階段只傳 solution、不傳完整對話史**。

定量結果：ChatDev 的 Completeness 0.5600 / Executability 0.8800 / Consistency 0.8021 / Quality 0.3953，顯著優於 GPT-Engineer（Quality 0.1419）與 MetaGPT（0.1523）。但代價明確：耗時為 GPT-Engineer 的 9.50 倍、token 為 3.20 倍。

**跨文獻判讀（Q4）**：「多開幾個 agent」本身沒有價值。ChatDev 的消融顯示，**移除角色設定使 Quality 跌 0.1741、Executability 跌 0.3000，是所有消融中影響最大的一項**；相較之下，去除 communicative dehallucination 僅跌 0.0859。Generative Agents 的 25 個 agent 之所以能湧現派對協調，前提是每個 agent 擁有各自的記憶流與局部視圖（非全知環境），而非共享同一提示。Mixture-of-Agents（S4）提供了同類場景的量化佐證：異質多模型 proposer（n=6）達 61.3%，而同模型多次採樣僅 56.7%。結論是：**收益來自異質性與角色專用化，不是數量**。

### D. Agent 評估與可靠性

**多環境分域：AgentBench（P6）**。AgentBench 用 8 個環境（Code: OS/DB/KG；Game: DCG/LTP/HH；Web: WS/WB）與 29 個模型，設計上的一個亮點是**不放棄部分得分**：KG 用 Answer F1，LTP 用 Game Progress（已猜出 bullet 數／該謎題總數），而非一律端到端二元判斷。這對事件抽取極有啟發——多源抽取本質是「部分抽取 + 部分正確」，用全對／全錯的 SR 衡量會丟失大量診斷資訊。

其失敗原因分解（Completed / CLE / Invalid Format / Invalid Action / TLE）顯示不同環境的瓶頸完全不同：DB 的 53.3% 失敗是 Invalid Format、KG 的 67.9% 是 TLE、HH 的 64.1% 是 Invalid Action。這種分解可直接遷移為抽取管線的失效歸因工具。商業與開源差距同樣顯著：gpt-4 OA 4.01，最佳開源 codellama-34b OA 0.96，仍低於 gpt-3.5-turbo 的 2.32。

需注意的文獻細節：AgentBench **沒有獨立的 Limitations 章節**，「環境飽和」一詞全文未出現（最接近的表述是 Web Shopping 分數偏高會影響樸素平均，作者因此採用 Weight-1 加權）；作者亦**未做污染檢查或記憶化檢測**。

**可靠性度量：τ-bench（P7）**。這是本綜述認為方法論價值最高的一篇。它把任務形式化為 POMDP，並採用**終態資料庫匹配**作為獎勵：`r = r_action × r_output ∈ {0,1}`，其中 r_action 要求最終 DB 狀態與唯一標註的目標狀態完全一致，r_output 要求回覆包含所有必要資訊字串。論文明確拒絕 LLM-as-a-judge——對話內容、存取路徑、使用者表述均可不同，只要終態正確即算成功。

最關鍵的貢獻是 **pass^k 指標**：

$$\mathrm{pass}^{\wedge k} = \mathbb{E}_{\mathrm{task}}\left[\frac{\binom{c}{k}}{\binom{n}{k}}\right]$$

即同一任務執行 n 次、其中 c 次成功時，k 次獨立試驗**全部**成功的機率（以任務為單位平均）。其結果是本綜述最重要的單一數據：**gpt-4o 在 τ-retail 的 pass^1 為 61.2，但 pass^8 掉到 25% 以下**。用最平實的話說——約四分之三的「成功率」其實是同一語義反覆運氣好。這意味著線上系統中多數使用者都會撞上一次失敗，而單一報告分數完全掩蓋了這件事。

政策消融則量化了「規則依賴度」：移除領域政策後，gpt-4o 在 τ-retail 僅由 61.2 降至 56.8（−4.4pp），但在 τ-airline 由 33.2 跌至 10.8（−22.4pp）。結論是**規則越反直覺，政策提示的邊際價值越大**——零售規則貼近預訓練常識，航空規則複雜且反直覺。gpt-3.5-turbo 在兩域的變動都極小，說明它基本上沒在用那些複雜規則。

另需留意 τ-bench 的自我批判：作者明確指出 `r=1` 是**必要非充分條件**——agent 可能直接執行退貨、終態正確，卻未先取得使用者明確確認，違反政策仍得滿分。以及其原任務已過期、需遷移至 τ³-bench。

**安全與可復現：AgentDojo（S3）**。這篇 NeurIPS 2024 D&B 論文提供了本綜述中唯一直接的安全實證。GPT-4o 的無攻擊效用 69.00%、受攻擊效用 50.08%、定向攻擊成功率 47.69%。防禦的代價極為清晰：純提示注入檢測器把攻擊成功率壓到 7.95%，**卻讓無攻擊效用從 69.00% 崩到 41.49%（−27.5pp）**——它在多數情況下並不是「防禦成功」，而是「拒絕工作」。唯一同時達成低攻擊率（6.84%）與高效用（73.13%）的是工具隔離。這直接支撐 Q5。

**跨文獻判讀（Q1、Q2、Q7）**：把 P6 與 P7 並置，可得本綜述最核心的方法論主張——**這些論文測的不是同一件事**。ReAct 測「單次任務是否完成」，AgentBench 測「8 個異質環境的加權總分」，τ-bench 測「在對話與政策約束下的終態正確性與跨試驗一致性」，WebThinker 測「知識密集推理與長報告品質」。AgentBench 本身以「先按模型間平均分縮放再平均」的 OA 聚合，即已承認各環境不可直接相加；τ-bench 更進一步以 pass^k 而非單次成功率為主指標。因此**文獻覆蓋度的真正瓶頸不是論文太少，而是各論文使用互不相通的度量語言**。

另一個必須正視的問題是**基準自身的衰減**。GAIA（S2）作者自陳基準會因兩種原因衰減：預訓練資料的災難性污染，以及網頁上所需資訊的消失，並主張需「逐年淘汰失效題目並加入新題」；τ-bench 官方倉庫已明確標示原任務過期。基準的半衰期正在成為 agent 研究的第一性限制。

### E. Agent 實際應用

**WebThinker（P8）是本方向最具代表性的文獻**，也是與博士研究場景最直接相關的一篇。它解決的問題是：大型推理模型（o1、DeepSeek-R1）長程推理能力強，但依賴靜態內部知識，在知識密集任務上受限，且難以產出需綜合多樣網路資訊的完整研究報告；既有 deep search agent 多依賴預定義工作流的 RAG，限制了模型自主深挖的能力。

架構上分三個角色：主 LRM（QwQ-32B，負責編排與推理）、Deep Web Explorer（同一 LRM 驅動的子行程，負責遞迴搜尋與導航）、助手 LLM（Qwen2.5-Instruct，負責文字操作——寫章節、改報告、壓縮網頁摘要）。共 5 個工具：Search（Bing Web Search API，k=10）、Link & Button Clicking（Crawl4AI 抓取全文）、Deep Web Explorer（高層封裝）、以及三個報告工具 Section Writing / Report Checking / Report Editing。

結果：GAIA 48.5、GPQA 70.7、WebWalkerQA 46.5、HLE 15.8，全面超越 Search-o1-32B（39.8 / 67.2 / 34.1 / 10.8）與 OpenAI Deep Research（GAIA 67.4 / HLE 26.6 的對照）。

**消融數據是這篇論文最有價值的部分**，因為它直接指出了什麼機制真正在起作用：

| 消融變體 | 四任務綜合均分 | 報告生成均分 | 解讀 |
|---|---:|---:|---|
| WebThinker-32B-RL（完整） | 45.4 | 8.1 | 基準 |
| w/o Training（Base） | 42.1 | 8.0 | **RL 對報告生成幾乎無增益** |
| w/o Link Clicking | 42.6 | — | 淺搜尚可，深挖才是關鍵 |
| w/o Deep Web Explorer | 38.3 | 7.7 | 移除整體探索能力影響最大 |
| w/o Report Check & Edit | — | 7.7 | Coherence 由 7.9 驟降至 6.9 |
| w/o Auto. Report Draft | — | 6.6 | **「邊搜邊寫」是報告品質主因** |

兩個結論：其一，**報告品質主要來自「檢索—撰寫交錯的即時合成」，而非模型訓練**（去訓練僅 8.1→8.0，去自動撰寫則 8.1→6.6）；其二，**深挖優於淺搜**（去 Explorer 42.1→38.3，僅禁連結點擊 42.1→42.6）。

上下文工程同樣值得借鑑：三個報告工具的執行結果**不回注主推理鏈**（由助手 LLM 直接修改共享狀態）；Report Checking **只回注大綱**（所有 section/subsection 標題）而不注入正文；長網頁以 click intent 摘要壓縮——即先宣告「我要從這個頁面找什麼」，再讓摘要器依此意圖壓縮。論文也誠實列出三項限制：無法處理多模態、工具種類有限、不支援 GUI 式網頁探索。

## 五、批判性分析：八項主張

本節對應教師評分維度中的「批判性分析」（20%）。每項主張採「主張 → 支持證據 → 反面證據與風險 → 對博士研究的啟示」四段式，完整表格見文獻矩陣「批判性分析」工作表。

### Q1｜各論文使用互不相通的度量語言，跨論文分數不可直接比較

**主張**：這個領域的瓶頸不是論文太少，而是度量語言互不相通。ReAct 的 HotpotQA EM 27.4 與 WebThinker 的 GAIA Pass@1 48.5 測的是不同能力族；AgentBench 以縮放後加權的 OA 聚合，本身即承認各環境不可直接相加；τ-bench 以 pass^k 而非單次成功率為主指標。**反面證據**：τ-bench 已把統一推到底（同一套 policy + state-match 框架跨兩域），代價是僅覆蓋零售與航空兩個客服域，airline 僅 50 任務。**啟示**：Border Event Intelligence Agent 應自建「來源域 × 事件欄位」雙維度矩陣，明確聲明每格用哪個指標，而非引用一個通用 agent 分數代表本系統能力。

### Q2｜單次成功率嚴重高估實際可靠性（平均值掩蓋尾部崩潰）

**主張**：「Agent 能做」與「Agent 可靠地做」是兩件事。gpt-4o 在 τ-retail 的 pass^1 為 61.2 但 pass^8 < 25%，線上系統中多數使用者都會撞上一次失敗。ChatDev 的成本表亦顯示「重試到成功」的工程代價同樣被平均分掩蓋。**反面證據**：pass^k 的組合數形式假設同任務多次試驗近似獨立同分布，實際上使用者表述隨機性與任務難度異質性會使 pass^k 高估真實可靠性；且 k 的選取尚無標準約定。**啟示**：驗收須同時報 pass^1 與 pass^k（建議 k=3、k=8），且重試變因應為「同一事件、不同來源表述」，而非「同一輸入重跑」——否則衡量的是模型採樣穩定性，不是系統穩健性。

### Q3｜「多想一步」不等於「想對一步」

**主張**：顯式增加思考／計劃步驟是 agent 框架的通用賣點，但沒有證據顯示它提升可靠性。τ-bench 的 `think` 函數消融無增益；Reflexion 消融顯示只有試錯而無歸因時性能反降（0.60→0.52）；真正有效的是能改變動作選擇的機制。**反面證據**：上述消融多在特定環境與特定模型上進行，跨環境可推性未經驗證；Reflexion 的 0.60→0.52 僅觀察於 50 題的 HumanEval Rust 子集。**啟示**：改進方向應是「可驗證的動作空間」——工具讀寫分離、欄位級斷言、來源不符時的選擇性放棄——而非在提示裡加更長的思考模板。

### Q4｜多智能體的收益來自異質性與角色專用化，不是智能體數量

**主張**：ChatDev 消融中移除角色設定影響最大（Quality −0.1741、Executability −0.3000），遠大於去除去幻覺溝通（−0.0859）；Generative Agents 的湧現協調前提是各 agent 擁有各自記憶流與局部視圖；WebThinker 徹底分離「誰規劃／誰取證／誰寫入」。MoA 佐證異質多模型（61.3%）優於同模型多次採樣（56.7%）。**反面證據**：多智能體 token 成本顯著上升（ChatDev 3.20×）；角色設定的收益與「更長提示」難以完全區分；Generative Agents 的協調指標僅 25 agent × 2 天。**啟示**：應採「角色即職責邊界」設計——來源蒐集者（只讀）、事件抽取者、衝突檢測者、格式化者，各角色的可用工具與可見上下文嚴格隔離，而非共用單一上下文。

### Q5｜安全防禦與任務效用存在可量化的此消彼長

**主張**：最好的安全防禦往往是把 agent 打成不會幹活的 agent。PI detector 把定向 ASR 從 57.69% 壓到 7.95%，但無攻擊效用從 69.00% 崩到 41.49%（−27.5pp）；唯一同時達成低 ASR（6.84%）與高效用（73.13%）的是工具隔離。因此任何 agent 可靠性報告都必須是雙指標的。**反面證據**：AgentDojo 僅 4 環境、97 任務、629 用例；Slack suite 攻擊成功率 92% 而 Travel 第 6 個注入任務為 0%，跨 suite 不可直接比較；各版數值不同，引用須標版本。**啟示**：事件抽取系統必然攝取第三方網頁／PDF 內容（注入置於工具輸出末尾時對 GPT-4o 的 ASR 最高約 70%），設計上應採「讀寫分離 + 最小權限 + 來源隔離」而非更嚴格的內容過濾，並在報告中同時給出抽取效用與注入成功率。

### Q6｜檢索召回與接地仍是瓶頸，但多數框架把它當成已解決問題

**主張**：ReAct 的 23% 失敗源於非資訊性檢索；ToolLLM 的 NDCG@1 78.0 意味約 22% 的正確工具首選即遺失；WebThinker 移除 Deep Web Explorer 綜合均分 42.1→38.3，遠大於僅禁連結點擊的 42.1→42.6。**反面證據**：WebThinker 的消融來自其自身 Glaive 任務與 LRM 主幹，不能直接外推至通用事件抽取；ReAct 的 23% 是在作者刻意弱化的 Wikipedia API 條件下取得。**啟示**：應把「來源召回率」與「欄位填寫正確率」拆成兩個獨立維度，並設置專門的「來源有效性檢查」——例如 click intent 式：先宣告要找什麼，再評估找到的內容是否回應了該問題。

### Q7｜基準自身會失效，且失效速度可能快於方法迭代速度

**主張**：GAIA 作者預警基準會因預訓練資料污染與網頁資訊消失而衰減，主張逐年淘汰失效題目；τ-bench 倉庫已聲明原任務過期需遷移 τ³-bench；ToolLLM 的 RapidAPI 是動態第三方服務，導致無法為每條測試指令固定唯一 ground-truth 路徑。**反面證據**：基準維護需持續投入，對資源有限的實驗室是實際負擔；GAIA 自陳「question creation can hardly be automated」。若追著新基準跑，實驗設計會被基準的更新節奏綁架。**啟示**：博士研究若自建事件抽取基準，必須同時設計「失效偵測與輪換」機制（來源可達性週期性探測、答案分布漂移監測）——這在多口岸跨年資料場景尤其真實。

### Q8｜「證據可追溯性」至今沒有被任何主流 Agent 基準正式評分 ← 最大空白

**主張**：這是本綜述判定的最大研究空白。GAIA 明確只評最終答案、不評推理軌跡，並把「引入人工或模型輔助的軌跡評估」列為未來工作；AgentBench 雖提供失敗原因分解，但分解的是「智能體為何失敗」，而非「其結論由哪些證據支撐」；WebThinker 以 listwise LLM-as-a-Judge 評報告品質，其 Factuality 維度評的是報告敘述本身，而非證據鏈的完整性。多源資訊整合的核心其實是 provenance，卻沒有基準在評它。

**反面證據**：Generative Agents 已在系統層面實現了「摘要 + because of 1,2,8,15 引用指標」的雙層結構，證明技術上可行，但該結構只服務於 agent 自身的長期記憶，尚未被提升為通用評分維度；GAIA 亦承認理想助手「應給出來源引用或選擇最可信來源並解釋」但當前無法自動評分。

**啟示**：這正是 Border Event Intelligence Agent 最有機會做出原創貢獻的地方——把「每筆事件記錄都必須攜帶來源 spans 與信心度，且可被確定性檢查器驗證」設計成一級目標，並以可核驗的方式報告。**這項設計無法從任何一篇現有論文直接借用，必須自行建立方法論。**

## 六、與博士研究的銜接：Border Event Intelligence Agent 的設計建議

以下建議皆為**設計推導**，非實證結論——本輪未實作任何系統。

| 設計面向 | 文獻依據 | 具體建議 |
|---|---|---|
| **證據可追溯性設為一級目標** | Q8；P3 的「摘要 + 引用指標」結構 | 每筆事件記錄強制攜帶 `evidence_spans`（來源 URL、段落位置、原文摘錄）與 `confidence`，並可被確定性檢查器驗證 |
| **評估雙維度** | P6 的部分得分設計；Q6 | 分別報「來源召回率」（該來源是否被檢索到）與「欄位填寫正確率」（時間／地點／類別／影響範圍各自的準確度），不混為單一 SR |
| **可靠性指標** | Q2；P7 的 pass^k | 同時報 pass^1 與 pass^k（k=3、8）；重試變因為「同一事件、不同來源表述」 |
| **角色即職責邊界** | Q4；P5 消融；P3 非全知設計 | 來源蒐集者（**只讀**工具）· 事件抽取者（填欄位）· 衝突檢測者（比對多源）· 格式化者（寫結構化記錄）；各角色上下文嚴格隔離 |
| **可執行的驗證判據** | Q3；P5 的編譯／執行回饋 | 以 schema 校驗器、欄位級斷言、引用存在性檢查器替代 LLM 主观評分；對證據不足的欄位給出顯式棄權標記而非猜測 |
| **接地優先的順序** | P1 的幻覺抑制數據 | 「先檢索再作答」作為預設順序；每步分解為「要找什麼 → 去哪個源 → 取到什麼」，使每步可審計、可定位錯誤 |
| **來源有效性檢查** | Q6；P8 的 click intent | 檢索前先宣告抽取目標，檢索後評估內容是否回應該目標；避免 ReAct 式「非資訊性檢索」（23% 失敗來源） |
| **安全邊界** | Q5；S3 | 檢索內容一律視為**資料而非指令**；採讀寫分離與最小權限；報告同時給出抽取效用與注入成功率 |
| **基準維護機制** | Q7 | 自建事件抽取基準需內建失效偵測與輪換（來源可達性、答案分布漂移） |
| **複雜請求的完整性** | P7 失敗分析（複合請求部分完成佔 19%） | 單列「部分完成」指標（已抽取條數／應抽取條數），不與全錯混為一類 |

**明確不主張的事項**：（i）本輪未實作 Border Event Intelligence Agent，無任何實測數據；（ii）Agent 提供的是可追溯的外部資訊，其對客流預測的增益屬未經驗證的假說；（iii）Agent 本身不解決負遷移預測問題——負遷移是跨節點特徵分布差異導致的統計學習現象，與 Agent 的資訊獲取能力屬不同因果層級。

## 七、研究空白與後續工作

依據前述分析，本綜述識別出四個優先級次序的研究空白：

1. **證據可追溯性的評分方法學**（Q8，信心度：高）。可由兩個方向切入：其一，為結構化抽取建立「來源 spans + 信心度 + 確定性檢查器」的驗證協議；其二，設計類似 AgentBench 失敗歸因五分類的 provenance 失效分類（例如「引用不存在」「引用與結論矛盾」「引用不足以支撐結論」）。
2. **可靠性指標的異質任務聚合**（Q1、Q2，信心度：高）。pass^k 已提供基礎形式，但 k 的選取與任務異質性下的聚合方式仍無標準；可比較「同事件不同表述」與「同表述不同來源」兩種變因對 pass^k 的影響差異。
3. **探索性不足場景的反思機制**（P2 的 WebShop 失敗實驗，信心度：中）。這是 Reflexion 明確留下的空白，也是多源廣度檢索場景的直接困境；MoA 式的多樣性 proposer 或 DFSDT 式回溯可能是候選解，但需實證。
4. **基準壽命週期管理**（Q7，信心度：中高）。面向資源受限實驗室的輕量失效偵測方法（例如以低成本探測任務定期重測基準的可解性與答案漂移）。
