## 四、最終選定：P1 ReAct

### 4.1 選定結論

**最終複現對象：P1 ReAct — *ReAct: Synergizing Reasoning and Acting in Language Models*（Yao et al., ICLR 2023）**

### 4.2 選擇理由

1. **核心方法是最純粹的「架構層」機制**。ReAct 的技術貢獻是 prompt 格式與交錯循環本身（Â = A ∪ L、`c(t+1)=(c(t), â(t))`、`Thought/Action/Observation`），完全在算法層面，不依賴訓練、不依賴付費 API、不依賴任何外部服務授權。在本機受限環境下，這是唯一能做到「**忠實複現核心方法**」而非「近似模仿」的候選。

2. **原論文提供了可直接對照的定量結構**。Table 1 的 Standard / CoT / CoT-SC / Act / ReAct / CoT-SC→ReAct / ReAct→CoT-SC 七條 baseline，加上 Table 2 的幻覺率人工分析（成功案例假陽性 ReAct 6% vs CoT 14%），構成一個完整的對照框架——本次複現的四條件設計是它的最小子集，可直接與原文對齊。

3. **關鍵數據雙雙實測可得**。HotpotQA distractor validation parquet 已成功下載（27.4 MB）；`api.wikimedia.org` 實測可支援 ReAct 的 `search`（返回 wiki 頁前 5 句、不存在時返回 top-5 相似實體）與 `lookup`（返回包含目標字串的下一句）兩種核心動作的語義等價實現。

4. **AT3 ① 的判讀已預先標記了複現陷阱，這本身就是複現價值所在**。AT3 ① 指出：常見說法「ReAct 在 HotpotQA 超越 CoT」實際有誤——純 ReAct EM 27.4 **低於** CoT-only 29.4，35.1 實為 ReAct→CoT-SC 混合策略。因此本次複現必須**同時實現 CoT 與 Act-only 兩條 baseline**，才能判定交錯格式在何種條件下真正有效；這使複現本身具備批判性，而非單純跑數字。

5. **風險最低**。相較候選 2（沙箱執行 LLM 生成程式碼）、候選 3（資料不可得）、候選 7（地板效應）、候選 9（需人類評估），ReAct 的失敗模式僅為「模型能力不足導致絕對分數偏低」——這是**可如實報告、可歸因於資料規模與模型規模的預期差異**，而非讓實驗失去意義的結構性缺陷。

### 4.3 誠實聲明（事先載明，避免事後合理化）

- 本次為**簡化複現**，非完整複現。原論文用 PaLM-540B（含 GPT-3 附錄），本機僅能用 3B/7B 級開源模型，**絕對 EM 必然顯著低於原文 27.4 / 29.4**。
- 檢索工具以 `api.wikimedia.org` 重建，**語義等價但檢索質量與原論文自建的簡易 Wikipedia API 未必相同**（原文明示其 API「significantly weaker than state-of-the-art retrievers」）。
- 本次複現的驗收標準設定為：**四條件的相對排序與幻覺率方向是否與原文一致**，而非絕對分數是否接近。
- 依任務書要求：本次複現範圍**僅限 AT3 ②**，不啟動 ③ Agent 工作任務、不提前撰寫 Final Report；不將香港口岸資料或博士研究內容併入本次作業。
