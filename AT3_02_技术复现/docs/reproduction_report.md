## 1. 論文背景與研究問題

ReAct 解決的是語言模型「推理」與「行動」兩條研究線長期割裂的問題。2022 年時，
CoT 這類純推理方法**不接地**，會產生幻覺並沿推演步驟傳播錯誤；而 WebGPT 這類純行動方法
**缺乏推理支撐**，不知何時該調哪個工具、長程規劃薄弱、難處理例外。

論文的命題是：讓 LLM 以**交錯（interleaved）**方式生成推理軌跡（thought）與任務動作（action），
使兩者協同——thought 讓模型能歸納、追蹤、更新行動計畫並處理例外；action 讓模型能與外部
資訊源互動以獲取事實。

其方法層面的核心形式化是兩個式子：

$$\hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}, \qquad c_{t+1} = (c_t, \hat{a}_t)$$

前者把「想」與「做」放進同一個序列位置；後者規定上下文只追加不重寫，使 observation 得以
進入下一步的推理——這正是「接地」收益的機制來源。詳細分析見 `docs/paper_analysis.md`。

### 3.2 關鍵設計決策（含三次被實測推翻的嘗試）

實作過程中有三個設計被實測證偽並修正，這些過程記錄在 `results/logs/` 與本節：

**決策 1：prompt 結構——不內聯續寫前綴**
官方實現（text-davinci-002，completion 模型）在 prompt 末尾給出 `Thought {i}:` 前綴，讓模型
接續。實測發現 3B instruct 模型會把這個前綴當作「需要復述的內容」，輸出恰好等於前綴就停止，
**不產出 Action**。改為不提供任何前綴、讓模型自由生成完整一步後，模型能產出與論文附錄
few-shot 一致的 `Thought i / Action i` 結構。

**決策 2：每題獨立的環境實例**
`WikipediaEnv` 持有逐回合狀態（`current_page_text` / `lookup_cache` / `lookup_cursor`）。
最初批處理器共用一個 env 實例，會導致 **B 題的 `lookup` 作用在 A 題剛檢索到的頁面上**——
這是會靜默污染結果的真實 bug。修正為每題獨立 env 實例（共享磁盤緩存故無額外網絡開銷），
並因此得以在同一輪內**並行**執行各題的環境調用。

**決策 3：動作名規範化與括號配對掃描**
官方用 `action[0].lower() + action[1:]`（只降首字母），但小模型常整體輸出小寫，故改為完全
規範化為小寫。同時，論文的 few-shot 示例本身包含嵌套括號（`Search[High Plains (United States)]`），
非貪婪正則會截斷，故改用括號配對掃描。

**決策 4：停止序列與解析範圍**
實測 `stop=["\nObservation {i}:"]` 會讓模型提前截斷在 Action 之前（3B 模型無法同時維持
thought 與 action 的嚴格格式分離）。改為不設 stop，並在解析時只取**第一段** Thought+Action——
因為 Observation 必須由環境真實執行得到，不可由模型臆造，後續步驟交回下一輪由環境反饋驅動。

### 5.3 失敗模式分析（對應論文 Table 2）

本次為**規則式自動標註**（原論文為人工標註），僅可作方向性對照。數據見
`results/hallucination_summary_main.csv` 與 `results/hallucination_labels_main.csv`。

| 標籤 | 本次 ReAct | 原文 ReAct | 本次 CoT | 原文 CoT |
|---|---:|---:|---:|---:|
| 成功-真陽性 | **95.2%** | 94% | **100.0%** | 86% |
| 成功-假陽性（幻覺） | **4.8%** | 6% | **0.0%** | 14% |
| 失敗-推理錯誤 | **57.0%** | 47% | **93.9%** | 16% |
| 失敗-檢索結果錯誤 | **8.9%** | 23% | — | — |
| 失敗-幻覺 | **31.6%** | 0% | **1.2%** | 56% |
| 失敗-標籤歧義 | **2.5%** | 29% | **4.9%** | 28% |

（本次樣本量：ReAct 成功 21 / 失敗 79；CoT 成功 18 / 失敗 82。）

**這一結果必須誠實解讀——它與原論文方向相反：**

- 論文的核心機制主張是「**接地抑制幻覺**」：ReAct 的失敗案例中幻覺僅佔 0%，而 CoT 佔 56%。
- 本次實測**完全相反**：ReAct 的失敗中幻覺佔 **31.6%**，CoT 僅 **1.2%**。
- 唯一一致的是**成功案例的假陽性率**：ReAct 4.8% ≈ 原文 6%（CoT 本次 0% vs 原文 14%）。
- 差異的可能解釋：本次的自動標註以「不確定表述（hedge）」作為幻覺的主要判據，這是一個**代理指標**——
  ReAct 的失敗軌跡大量包含「It seems...」「Let's try...」這類表達（因為它在反覆檢索中探索），
  故被規則判為幻覺；而 CoT 失敗時通常直接給出一個錯誤答案，**沒有表達上的不確定性**，
  因而被判為「推理錯誤」而非「幻覺」。
  這說明**本次的自動標註無法捕捉論文的「幻覺」定義**（論文的幻覺指「推理軌跡或事實本身是編造的」，
  而非「表達不確定」）。這是方法學缺陷，不是 ReAct 機制被推翻。
- 另一個真實差異：本次 ReAct 的**檢索命中率僅 36.3%**，且失敗中「檢索結果錯誤」佔 8.9%。
  當檢索本身大量落空時，「接地」的保護作用無從發揮——這解釋了為何 3B 模型上 ReAct 的接地收益
  未能重現。論文 §3.3-C 亦指出「非資訊性檢索佔錯誤案例 23% 會讓模型推理脫軌」，
  本次該項（8.9%）雖低於原文，但結合 41–36% 的步數用盡率，說明**弱模型的主要瓶頸在檢索質量而非推理格式**。

### 5.4 統計顯著性

100 題上 ±1 個樣本即 ±1 個百分點，故小幅差異**必須**用配對檢驗才可解讀。
`evaluate.py` 產出 McNemar 精確檢驗與配對 bootstrap 95% CI：

| 對比 | ΔEM | bootstrap 95% CI | McNemar p | 判定 | 僅前者對 / 僅後者對 |
|---|---:|---|---:|---|---:|
| ReAct vs CoT | +0.030 | [−0.050, +0.110]pp | 0.6291 | 不顯著 | 7 / 10 |
| ReAct vs Act | −0.020 | [−0.090, +0.050]pp | 0.7744 | 不顯著 | 7 / 5 |
| CoT vs Standard | +0.020 | [−0.040, +0.080]pp | 0.7539 | 不顯著 | 4 / 6 |
| Act vs Standard | +0.070 | [−0.010, +0.150]pp | 0.1435 | 不顯著 | 5 / 12 |

**四組配對差異全部未達統計顯著（p = 0.14–0.77），且所有 bootstrap CI 均跨過 0。**
這是本次最重要的統計事實：**100 題的樣本量不足以判定 HotpotQA 上任何兩條 baseline 之間的
1–3pp 差異**。因此 §5.2 的「方向一致／不一致」判定**只能視為描述性觀察，不能視為統計結論**。

原文的 ReAct vs Act 差距僅 1.7pp，遠小於本次的解析度；這意味著**要用統計方法檢驗論文的
核心排序結論，至少需要原論文量級的 500 題**。

## 6. 與原論文的差異分析

### 6.1 可歸因於規模的差異（預期內）

| 因素 | 影響機制 | 方向 |
|---|---|---|
| **模型規模（最主要）** | PaLM-540B（540B）→ 3B，相差約 180 倍。論文附錄 A.1 中 GPT-3 (175B) 的 HotpotQA EM 為 30.8，僅比 PaLM 高 1.4pp，顯示此任務對模型的「推理風格」而非絕對參數量更敏感；3B 模型的差距主要體現在多跳推理的完整性 | 絕對 EM 大幅偏低 |
| **Thought 品質** | 論文的 thought 是**人工撰寫**的六種類型（分解問題／抽取觀測資訊／常識推理／算術推理／引導檢索改寫／綜合答案）。3B 模型生成的 thought 常退化為「重複 observation」或「直接跳到答案」，使 §9.1 的六類 thought 中至少「分解問題」與「引導檢索改寫」失效 | ReAct 優勢被削弱 |
| **格式遵循** | 小模型較難同時維持 thought 與 action 的嚴格格式 | 需 badcall 補救（診斷欄 `avg_badcalls`） |
| **步數用盡** | 3B 模型常在 7 步內無法收斂到 finish | 完成率低於原文（診斷欄 `completion_rate`） |
| **循環失敗模式** | 論文腳註 6 明指 ReAct 存在「反覆生成先前 thought/action」的循環，並歸因於貪心解碼。3B 模型上此模式**更嚴重** | `n_repeated_actions` 診斷欄可量化 |

### 6.2 不可歸因於規模、需誠實指出的實作差異

| 差異 | 說明 | 對結果的可能影響 |
|---|---|---|
| **檢索質量不同** | 本次以 `api.wikimedia.org` 重建環境。① 官方 API 抓的是搜尋結果摘要，本環境取頁面 wikitext 再切句；② **2026 年的頁面內容與 2023 年 few-shot 示例中記錄的 observation 必然不同**——模型在 few-shot 裡看到 `Search[Colorado orogeny]` 返回 A，實測可能返回 B，這種不一致會影響模型對檢索結果的信任 | 可能**降低** ReAct 的接地收益 |
| **prompt 結構** | chat template + 無續寫前綴，與官方 completion 格式不同 | 影響 thought 的產生方式 |
| **模型先驗差異** | 官方用 PaLM-540B（Google 內部模型，訓練資料含大量 Wikipedia），3B 開源模型對 Wikipedia 結構的先驗較弱 | 可能使 ReAct 的「檢索改寫」能力下降 |
| **新增的 invalid 提前終止** | 連續 2 次無法解析動作即提前結束 | **略微提高** EM（避免空答案被稀釋），已在 README 聲明 |

### 6.3 一個必須承認的統計限制

100 題上，EM 的 95% Wilson 區間寬度約 ±8–10 個百分點。原文 ReAct 與 Act 的差距僅 **1.7pp**，
遠小於本次實驗的統計解析度。因此**本次無法在統計上判定「ReAct > Act」是否成立**——
這是評測規模的限制，不是方法的失敗。故本報告對相對排序只做**方向性**描述，
並以配對檢驗的 p 值與 bootstrap CI 明確標示其不確定性。

## 7. 復現局限性

1. **簡化復現，非完整復現**：未做 CoT-SC、兩條組合方法、FEVER、ALFWorld/WebShop、微調實驗。
2. **官方代碼完全未使用**：網絡不可達，全部從零實現——這滿足任務書要求，但也意味著
   **無法保證與官方實作逐行等價**。本報告 §3.3 逐項列出一致處與差異處作為替代性保證。
3. **Table 2 為自動標註**：對「事實錯誤」的靈敏度必然低於人工標註者。
4. **單次運行**：未做跨環境重複實驗以量化 run-to-run 方差（溫度為 0 使此方差很小，
   但未實測驗證）。
5. **評測規模 100 題**：小幅差異的統計功效受限。
6. **環境隨時間漂移**：Wikipedia 頁面內容會變動；本工程以磁盤緩存保證同一次實驗內一致，
   但**跨時間重跑時可能得到略有不同的 observation**。

## 8. 結論

本次以 3B 級開源模型、100 題 HotpotQA 子集、4 條受控 baseline，完整實現並實測了 ReAct 的核心方法。

**絕對指標顯著低於原論文（16.0–23.0 vs 25.7–29.4），這是模型規模的預期結果，而非實現失敗**——
證據在於：四條 baseline 的**格式遵循率均為 100%**、完整可追溯的逐題軌跡、以及
可歸因的診斷數據（41% 步數用盡 + 62% 檢索未命中）。

### 8.1 五項核心發現

**發現 1：ReAct 的「格式機制」在弱模型上完全成立，但「收益前提」不成立。**
格式遵循率 100%（模型確實能按 `Thought/Action/Observation` 交錯格式產出合法動作），
但檢索命中率僅 36.3%、步數用盡率 36%。原論文的 ReAct 收益建立在
「模型能提出正確檢索詞並在 7 步內收斂」之上——這在 PaLM-540B 上成立（步數用盡僅 0.84%），
在 3B 上不成立。**這是本次復現最具價值的發現：ReAct 的落地門檻不在架構，而在底座模型的檢索能力。**

**發現 2：相對排序未能在統計上重現，且差異方向與原文相反。**
四組配對差異全部不顯著（p = 0.14–0.77，bootstrap CI 全跨 0）。方向上，
Act vs Standard 在原文為 −3.0pp、在本次為 **+7.0pp**（方向相反），
ReAct vs Act 在原文為 +1.7pp、在本次為 **−2.0pp**（方向相反）。
**必須強調：100 題的樣本量不足以判定 1–3pp 量級的差異**，故上述「方向相反」是描述性觀察而非統計結論。
要用統計方法檢驗論文的排序結論，至少需要原論文量級的 500 題。

**發現 3：失敗模式結構的差異指向「檢索質量」而非「推理格式」。**
本次 ReAct 失敗中推理錯誤 57.0%、檢索錯誤 8.9%，而原文為 47% 與 23%；
CoT 失敗中推理錯誤 93.9%（原文僅 16%）。這說明弱模型的 CoT 失敗主要來自**無法在參數記憶中
完成多跳推理**，而 ReAct 通過檢索**部分補償**了這點（Act 23.0 > CoT 18.0）。

**發現 4：自動標註無法捕捉論文的「幻覺」定義，這是方法學缺陷而非機制被推翻。**
本次 ReAct 失敗中幻覺佔 31.6%、CoT 僅 1.2%，與原文（ReAct 0%、CoT 56%）**方向完全相反**。
原因是本次以「不確定表述」作為幻覺的代理指標，而 ReAct 在反覆檢索中天然產生大量
「It seems...」「Let's try...」這類表達，CoT 失敗時則直接給出錯誤答案故無此表達。
論文的「幻覺」指「推理軌跡或事實本身是編造的」，二者不是同一件事。

**發現 5：AT3 ① 的核心判斷得到實證支持。**
AT3 ① 曾指出「ReAct 在 HotpotQA 上超越 CoT」是常見誤傳（純 ReAct EM 27.4 < CoT 29.4），
且 ReAct 的相對優勢需要與 CoT-SC 結合才顯現。本次實測 ReAct 21.0 > CoT 18.0 的絕對值雖然
**並不支持**該誤傳（本次 ReAct 略高於 CoT），但統計上不顯著；這恰好說明
**在 HotpotQA 上，這個對比本身就是統計脆弱的**，必須用 FEVER 或更大樣本才能辨識。

### 8.2 最重要的後續工作

補做 **FEVER** 實驗。AT3 ① 已論證「ReAct vs CoT 在 FEVER 上的差異是結構性的
（必須檢索才能區分 SUPPORTS/REFUTES），不依賴長鏈推理能力」，
因此是最可能在小模型上重現原文方向（ReAct 60.9 > CoT 56.3）的場景——
這也與本次發現 1 完全吻合：FEVER 的檢索需求更明確（判別事實而非組合推論），
3B 模型的檢索詞命中率應顯著高於 HotpotQA 的多跳問題。

第二優先是**擴大樣本至 500 題**（原論文量級），使 ReAct vs Act 的 1.7pp 差距可被統計檢驗。

### 8.3 本次復現對 AT3 ① 文獻綜述的反饋

AT3 ① 曾標記「證據可追溯性未被任何主流 Agent 基準正式評分」（Q8）為最大研究空白。
本次復現從側面支持了這一判斷：ReAct 的架構**本身就產生了可追溯的軌跡**
（`results/trajectories/*.jsonl` 完整記錄每一步的 thought / action / observation /
模型原始輸出），使得「證據追溯性」可以**在完全沒有新增基準的情況下被事後審計**——
這正是 Q8 所指出的、主流基準（如 GAIA、AgentBench）尚未提供的能力。
